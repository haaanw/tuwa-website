<is_inline_tradeoff_resolution>
**Decision: Keep `is:inline` on the BaseLayout counter script. Inline a 3-entry locale→BCP-47 ternary inside the script. Do NOT import from format.ts.**

Rationale:
1. The script is animation-critical (fires inside an IntersectionObserver callback driving the homepage hero counter reveal). Dropping `is:inline` causes Astro to bundle/defer it, which can shift execution relative to first paint and risk a visual regression on the count-up animation.
2. Duplication is 1 ternary expression (~40 chars), not a meaningful maintenance surface. `LOCALE_TAG` in `format.ts` remains the documented source of truth — a code comment in BaseLayout.astro will point future editors there.
3. The inline script cannot use ESM imports; the only alternative is the bundled-script path, which is the scope-expanding option.
4. Re-verifying the count-up animation FCP timing across en/zh/fr after a bundling change is out of scope for I18N-21.

Implementation: inside the inline script, replace `target.toLocaleString()` with `target.toLocaleString(tag)` where `var tag = locale === 'zh' ? 'zh-CN' : locale === 'fr' ? 'fr-FR' : 'en-US';` and `var locale = counter.getAttribute('data-locale') || 'en';`. Apply this transform at all 3 sites (BaseLayout.astro lines ~50, ~72, ~76 — the two `.toLocaleString()` call sites inside `[data-counter-target]` blocks plus any final-value assignment).
</is_inline_tradeoff_resolution>
